# dwhiepaint

Загружаешь фото — получаешь раскраску по номерам, готовую к печати: чистый
контур с пронумерованными областями, предпросмотр «как будет выглядеть
закрашенным», легенду «номер → цвет» с русскими названиями и подсказкой, какой
краской красить. Всё работает в браузере; тяжёлую обработку берёт на себя
отдельный Python-сервис.

Интерфейс на русском, светлая и тёмная темы, стеклянный Apple-подобный дизайн.

## Возможности

- **Умная сегментация.** Не наивный k-means по пикселям, а edge-aware пайплайн
  (SLIC-суперпиксели + палитра по средним Lab с весом по площади). Границы
  областей идут по реальным краям, а не по цветовому шуму.
- **Понимание сюжета.** Модель `rembg` (u2net) отделяет главный объект от фона,
  детектор лиц и карта краёв строят «карту важности»: мелкие детали (глаза,
  текст, звёздочки) сохраняются, а плоский фон упрощается в крупные чистые
  области.
- **Автоподбор числа цветов** с ручной донастройкой ползунком и пресетами
  детализации (Новичок / Стандарт / Детально).
- **Интерактивный просмотр результата:** зум/пан, переключение слоёв
  (оригинал ↔ закрашенный предпросмотр ↔ контур), подсветка всех областей
  выбранного цвета.
- **Форматы экспорта:** PDF (лист-раскраска с миниатюрами-ориентирами + лист
  легенды), PNG, масштабируемый **SVG** и **ZIP**-пакет со всем сразу.
- **Печать больших холстов** плиткой N×N листов A4 с метками реза, перекрытием
  и страницей-схемой сборки.
- **Подбор реальных красок:** для каждого цвета — ближайшая акриловая краска по
  CIEDE2000, а если точной нет, подсказка «смешать A + B».
- **Аккаунты и история** работ, публичные ссылки-шеринги, экспорт в 600 dpi.
- **Асинхронная обработка** с прогрессом по стадиям в реальном времени —
  тяжёлые фото и ML не упираются в таймаут запроса.

## Как это работает

```
загрузка фото
     │
     ▼
[analyze]  быстрый анализ + авто-подбор числа цветов        (синхронно)
     │
     ▼
[/jobs]    задача уходит в очередь Redis
     │
     ▼
[worker]   ARQ-воркер гоняет пайплайн, пишет прогресс по стадиям в Redis:
           объект/лица → суперпиксели → слияние → сглаживание →
           отрисовка → векторизация
     │
     ▼
[результат] палитра + контур (SVG) + предпросмотр; фронт опрашивает статус,
            backend сохраняет палитру в Postgres
     │
     ▼
[экспорт]  PDF / PNG / SVG / ZIP / плитка
```

Канонический выход пайплайна — **вектор (SVG)**: из него растеризуются и
экранный контур, и печатный PDF/PNG в нужном разрешении, поэтому линии остаются
чистыми на любом масштабе. Нумерация ставится в «полюс недоступности» области
(`shapely.polylabel`), так что цифра всегда попадает внутрь даже у вогнутых
фигур.

## Архитектура

| Сервис        | Технологии                                   | Роль |
| ------------- | -------------------------------------------- | ---- |
| `frontend`    | React 19 + TypeScript + Vite                 | UI, опрос статуса задач, экспорт |
| `backend-api` | ASP.NET Core (.NET 10) + EF Core + Npgsql    | авторизация (JWT), оркестрация, персистентность |
| `cv-service`  | Python 3.12 + FastAPI + OpenCV/scikit-image  | анализ, сегментация, экспорт |
| `worker`      | тот же образ, что `cv-service`, команда ARQ  | асинхронная обработка задач |
| `redis`       | Redis 7                                      | очередь задач + эфемерный прогресс |
| `postgres`    | PostgreSQL 16                                | пользователи, работы, палитры |

Разделение данных: **cv-service не имеет доступа к БД** — он держит только
эфемерный кэш по `image_id` и делится рабочими файлами с воркером через общий
том. Прогресс задач живёт в Redis (эфемерно), финальные результаты сохраняет
backend в Postgres. Фронт общается только с `backend-api`, который проксирует
запросы к CV-сервису.

## Быстрый старт

```bash
cp .env.example .env      # при желании поправьте пароль БД и JWT-секрет
docker compose up --build
```

Первая сборка `cv-service` небыстрая: в образ ставятся ML-зависимости и
предзагружается модель u2net (~176 МБ), чтобы не тянуть её в рантайме.

| Сервис      | URL                     |
| ----------- | ----------------------- |
| frontend    | http://localhost:5173   |
| backend-api | http://localhost:5000   |
| cv-service  | внутренний, порт 8001   |
| postgres    | localhost:5432          |

Проверка здоровья:

```bash
curl http://localhost:5000/health
curl http://localhost:5000/health/db
```

> Меняете код в `cv-service`? Пересоберите **и** пересоздайте оба сервиса,
> которые используют этот образ:
> `docker compose up -d --build cv-service worker`.

## Локальная разработка (без Docker)

- **backend-api:** `dotnet run --project backend-api/DwhiePaint.Api`
  (нужен Postgres на 5432; миграции применяются на старте).
- **cv-service:** из `cv-service/` — `pip install -r requirements.txt` и
  `uvicorn app.main:app --port 8001` (для очереди нужен запущенный Redis;
  синхронные `/analyze` и `/export` работают и без него).
- **frontend:** из `frontend/` — `npm install`, затем `npm run dev`. Обращается
  к backend на `http://localhost:5000` (переопределяется `VITE_API_BASE_URL`).

## Тесты и сборка

```bash
# CV-пайплайн (проще всего прогнать в образе, где стоят все ML-зависимости)
docker compose build cv-service
docker run --rm -v "$PWD/cv-service/tests:/app/tests:ro" dwhiepaint-cv:latest \
  sh -c "pip install --quiet pytest && python -m pytest tests -q"

# Фронтенд: типизация + сборка + модульные тесты
cd frontend && npm run build && npm run test

# Backend
cd backend-api && dotnet build
```

## Аутентификация и доступ к файлам

JSON/данные-эндпоинты требуют JWT (`Authorization: Bearer <token>`) и привязаны
к текущему пользователю. Байтовые эндпоинты изображений (`/original`,
`/cv-cache/…`) отдаются анонимно по непубличному UUID, чтобы их могли грузить
обычные теги `<img>`. На вход навешен rate-limiting (строгий на регистрации/входе)
и лимит размера загрузки.

## Известные упрощения

- **Набор красок — универсальный** (24 цвета), не привязан к конкретному бренду.
  Заменяется файлом `cv-service/data/paints_acrylic.json`.
- **Ссылки на изображения** отдаются по непубличному UUID, а не по подписанным
  URL — усиление доступа оставлено на будущее.
